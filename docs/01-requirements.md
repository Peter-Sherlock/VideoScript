# 01 需求：用户、目标、范围与成功标准

## 1. 用户与问题

| 用户 | 场景 | 痛点 |
|---|---|---|
| 品牌/电商的短视频创作者、运营 | 给某个产品写 15–60 秒的抖音/小红书/视频号脚本 | 卖点要准确（不能乱写功能和数据），时长要卡得住，还要符合品牌规范和广告法，改稿往返多 |
| 审核/法务同学 | 发布前核对脚本里的每个说法 | 不知道每句话依据哪份资料，难以逐条核对 |

**目标**：输入主题、受众、平台、目标时长、风格，结合产品素材与品牌规则，生成一份**有事实依据、满足时长限制、可直接编辑**的分镜脚本；做不到时要明确说明原因，而不是交一个“看起来像完成”的结果。

## 2. 输入与资料

| 输入 | 说明 | 是否关键 |
|---|---|---|
| topic / product | 主题或产品名 | 关键（至少其一） |
| platform | 抖音 / 小红书 / 视频号 / B站 / 快手 | 关键（影响标题长度等规则） |
| target_duration_sec | 目标时长（秒） | 关键（不能猜） |
| audience、style | 受众、风格 | 可缺省，Agent 可合理假设但必须写进风险 |
| must_include | 用户要求必须出现的要点（关键词） | 可选，硬性约束 |
| extra_requirements | 其它要求（可能包含违规要求，如极限词） | 可选 |
| 产品素材库 | [data/materials.json](../data/materials.json)：每条素材一个 ID、类型（feature / spec / effect_data / price / brand）、事实原文、出处、必需的免责说明 | 合成数据 |
| 品牌与平台规则 | [data/brand_rules.json](../data/brand_rules.json)：极限词、功能词表、效果表述规则、平台标题上限、语速与时长口径 | 合成数据 |

提供给 Agent 的工具：素材检索 `search_materials`、时长估算 `estimate_duration`、规则检查 `check_rules`，以及流程工具 `request_user_input`、`update_brief`、`submit_script`、`report_failure`。

## 3. 交付结果

每次运行输出 `output.json`（机器可读）+ `output.md`（可编辑），包含：

- **标题**
- **分镜**：镜号、画面、旁白、字幕、角标/免责说明、逐镜时长、素材来源 ID
- **预计总时长**（由工具计算，逐镜时长之和）
- **素材来源**：引用到的素材 ID、事实原文、出处
- **检查结果**：时长检查与规则检查，且两者绑定到同一个脚本版本
- **风险**（模型给出的假设/风险 + 系统记录的工具失败、规则提示）
- **任务状态**：`completed` / `needs_input` / `failed` / `incomplete`，附原因
- **修订记录**：每个版本的预计时长与检查结论；以及完整运行记录 `trace.jsonl` / `trace.md`

## 4. 范围

**做**：单 Agent + 本地工具的 CLI；DeepSeek（OpenAI 兼容接口）真实模型运行；离线 Mock 入口；故障注入；执行上限；独立核对脚本；单元/循环/场景测试。

**不做**（题目说明为非必需）：界面、线上部署、多 Agent、生产级 Runtime、真实素材库/向量检索、视频生成。

## 5. 成功标准（对应题目“必须验收”）

| 验收点 | 成功标准 | 对应用例 |
|---|---|---|
| 正常生成 | 状态 `completed`；每个含产品事实的分镜都有来源 ID；时长落在 [0.8×目标, 目标]；同一版本通过时长与规则检查 | 01、02、06、09 |
| 缺关键信息 | 不猜测平台/时长，调用 `request_user_input` 给出具体问题，状态 `needs_input`；用户补充后能继续 | 03、03b |
| 无素材 | 检索无结果时由模型决定改写查询或请求补充；不得在无素材时编写产品事实 | 04（改写后仍无→请求补充）、05（改写后命中→继续） |
| 工具失败 | 工具错误作为观察返回给模型，由模型决定重试或放弃；不能跳过检查直接交付 | 06（重试成功）、07（持续失败→明确失败） |
| 超时长后的修正或明确失败 | 超时后按工具给出的超出秒数压缩并**重新估算**；无法同时满足时 `failed` 并给出冲突点和建议 | 02b（用户自带约 38s 草稿→30s 内）、01/06（首稿超时→压缩）、08（3 秒放不下 7 个必含要点→明确失败） |
| 事实不可编造 | 无效果数据时不得出现“效率提升80%”等结论；数字、功能、效果均可追溯到素材 | 02（用户主动要求“效率提升80%”）、02b（草稿里写了“效率提升80%”）、规则单测 |
| 执行上限 | 达到轮数/调用上限时返回明确的 `incomplete` | 10 |
| 决策可追溯 | 运行记录包含步骤、工具参数、返回摘要、后续动作、模型给出的简要决策依据 | 全部 `trace.md` |
